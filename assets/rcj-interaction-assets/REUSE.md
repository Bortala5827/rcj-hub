# RCJ 互动资产 · 复用规则（Reuse Rules）

> 沉淀资产 ≠ 堆文件夹。规则的目的是：**下一次新产品开发，调用比重写快。**

## 1. 模块契约（新增模块必须守）

- 一个模块 = 一个文件夹，内含：
  - `index.html`：**自包含 demo**（HTML+CSS+JS 内联或同目录引用，打开即可看效果）
  - `README.md`：用途 / 技术 / 参数 / 接入片段 / 依赖声明
  - 源文件（`.js` / `.css`）尽量零依赖；非用不可的第三方（如 canvas-confetti）**显式写进 README 的「依赖」**，并优先本地 vendor 化，不引不明 CDN
- 对外暴露的 API 保持稳定；破坏性改动 → 升主版本（`v1`→`v2`），旧调用可共存一个过渡期
- 不依赖任何产品特有的全局变量（如 `window.RCJXxx` 之外的业务状态）

## 2. 版本号与缓存

- canonical 源里的引用默认带 `?v=YYYYMMDD` 日期戳；**部署前必须把 `?v=` 改成目标项目当前版本**，否则旧缓存会让线上看不到更新
- 复制进产品后，模块归产品所有；上游更新需手动同步（不做自动拉取，避免线上被意外改动）

## 3. 调用而非复制——何时该「抽」，何时该「写」

| 情况 | 动作 |
| --- | --- |
| 同样效果要在 ≥2 个产品出现 | 抽成资产库模块，产品里调用 |
| 仅为单个产品一次性效果 | 先写在产品内，跑通后再看是否值得沉淀 |
| 已有引擎能力可覆盖（Voice/Motion/Particle） | 优先扩引擎，不新开平行小游戏 |
| 小游戏功能高度特异、无复用价值 | 留在产品内，不进资产库 |

## 4. 不碎片化仓库

- ✅ 独立发展潜力的引擎单独立库：`rcj-voice-engine` / `rcj-ui-kit` / `rcj-interaction`
- ❌ 反对 `rcj-bubble-game1` / `rcj-bubble-game2` / `rcj-shake-game3`
- 同类小游戏统一收进 `rcj-interaction/relax/`（bubble / shake / particle / breathe 平铺）

## 5. 登记与索引

- 新增 / 升级模块后，**必须**同步两处索引：
  1. 本仓库 `assets-manifest.json`（interaction 层明细）
  2. RCJ Hub 的 `/assets` 资产总目录（跨层总览）
- 状态字段：✅ 已实现 / 📋 规划中 / 🚧 进行中

## 6. 视觉一致性

- 复用 RCJ 统一色板（见 rcj-hub `hub.v2.css` 的 `--accent` 等变量）
- 动效节奏统一：入场 `back.out`、呼吸 `sine`、解压 `elastic`
- 字体、圆角、阴影与品牌语言对齐，避免「拼凑感」
