# RCJ 自媒体矩阵 · 增长层策略

> 本文是 `RCJ-Product-Development-Framework.md` 在「增长 / 获客」维度的展开。
> 给负责内容生产的 AI（或换机后的你自己）在产出公众号 / 小红书 / 视频号内容前先读。

## 定位

自媒体矩阵是产品体系的**增长层**，不是独立业务。

- **前期（现在 → 产品打磨期）**：投入时间把两件事搭通——① 产品做扎实；② 内容管线（草稿填充、素材库）跑起来。
- **后期（产品稳定后）**：自媒体变成**低边际成本**的日常运营——每天定时发，不再占用大量精力。

这与框架「先做小工具 → 沉淀 → 按增长决定下一步」一脉相承：自媒体是产品长大后的增长引擎，而不是平行的另一摊事。

## 第一性原理

> 用**持续、诚实**的内容持续获客，并把流量沉淀成私域（微信公众号）；不靠一次性广告投放。

## 平台分工（已拍板）

| 平台 | 优先级 | 角色 | 形式 | 生产方式 |
|---|---|---|---|---|
| 微信公众号 | **第一优先级** | 私域主阵地、转化闭环 | 长文 + 贴图 | Playwright 草稿填充（仅存草稿）→ 人工审阅 + 手动发布 |
| 小红书 | 合规内容 | 站内互动引流（不主动导流） | 合规纯内容笔记 | 人工 / AI 写合规文案，不放外链 / 联系方式 |
| 视频号 | 自有渠道 | 过程记录、人设温度 | 录屏讲解 | 用户自录屏 + 口播，简单无特效 |

## 内容生产管线

- **长文（公众号）**：AI 写 `meta.json` → `build.js` 渲染 HTML → Playwright 填入公众号草稿（标题 / 作者 / 正文）→ **人工审阅 + 手动点发布**。
  - 🔴 **红线：只存草稿，绝不自动发布**（2026-08-09 用户拍板）。自动化止步于「草稿」，发布动作永远留给人。
- **贴图（公众号图片消息）**：配合长文的图片卡片，可日更；不受订阅号「每天 1 次群发」限制。
- **视频（视频号）**：用户自行录屏讲解自己的过程，**不做自动化制作、不加重特效**——简洁即是风格，花哨特效纯属多余。

## 节奏约束

- 订阅号每天仅 **1 次群发**：长文可多篇合成一次群发；贴图 / 视频号 / 小红书不受此限，可日更。
- 建议节奏：公众号每周 3–5 篇长文 + 每日 2–3 贴图；视频号 + 小红书按各自节奏同步。
- 排期靠「每日招录汇总」自动化喂素材（辅警 / 消防员公告即内容热点），不靠临时拍脑袋。

## 禁止事项

- ❌ 公众号**自动发布系统**（只存草稿，发布留给人）。
- ❌ 视频花哨特效 / 复杂剪辑（简洁录屏即可）。
- ❌ 小红书**站外导流钩子**（联系方式 / 外链 / 「看主页」「看置顶」均被平台监控限流）。
- ❌ 夸大 AI 能力（文案诚实，尤其面试 / 表达类产品，点评本质是「录音转文字→基于文字点评」）。

## 与产品体系的关系

- 自媒体是产品的**增长层**；素材来自产品资产层：音视频资料库（`rcj-media-assets`）、真题库、产品截图 / 录屏。
- 内容反过来给产品导流：公众号 canonical 教程文 ↔ 产品站互相引流（如「国内大模型免费 API 获取教程」↔ 辅警站）。

## 当前阶段

**v0 — 等产品打磨好，再全力做自媒体。** 前期把管线和素材库搭通，后期每天定时发即可。
