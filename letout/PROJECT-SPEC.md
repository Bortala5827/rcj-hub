# LetOut · 大声说 — 项目级技术规范（PROJECT SPEC）

> 本文件只定义 **技术实现**，不重复定义品牌理念。
> 品牌定位 / 人格 / 文化意象 / 边界 见上层文档：
> - `products/RCJ-产品生态总纲.md`
> - `products/Speak-Series-总体产品设计规范.md`（第十一节 ~ 第十二节）

**核心约束（来自系列规范）**：不是社交产品；不是心理治疗；是「低连接时代里的情绪出口」；尽情地释放；先出声；本地优先；用户拥有自己的数据。
文化意象：巴黎街头咖啡馆 —— 热烈 / 自由 / 释放 / 不隐藏 / 不要求坚强。

---

## 0. 技术栈

与 SoloSpeak 同源、共享底座（见 §1 共享模块）：

- 纯前端，零后端依赖。
- 静态托管：Cloudflare Pages，输出目录即仓库根。
- 原生 HTML / CSS / ES Modules，不引框架。
- 持久化：**IndexedDB**（与 SoloSpeak 同构，但默认不长期留存录音，见 §4）。
- 录音：`MediaRecorder` + `getUserMedia`（复用 `rcj-audio-core`）。
- 波形：`Web Audio API` + Canvas（复用 `rcorder/ waveform`，配色更热烈）。
- PWA：`manifest.webmanifest` + `sw.js`。

---

## 1. 共享模块（与 SoloSpeak 复用）

LetOut **不重复实现**录音与波形，直接引用 SoloSpeak 沉淀的共享层：

- `rcj-audio-core`（建议 Skill）：`recorder.js` + `waveform.js`。
  - LetOut 仅通过参数切换气质：`{ theme: 'letout', amplitudeScale: 1.4, color: '#ff5a5f' }`（振幅更大、配色更暖烈）。
- 两个产品各自维护独立的 IndexedDB 库名（`letout` vs `solospeak`），数据不互通（符合系列规范「连接产品，不制造用户关系」）。

> 若共享层尚未抽成 Skill，LetOut 初期可复制 `recorder.js` / `waveform.js` 并标注 TODO：待抽 `rcj-audio-core`。不要在 LetOut 里另写一套不同语义的录音逻辑。

## 3. 五种交互模式

LetOut 与 SoloSpeak 的根本区别：**尽情地释放**。提供五种出口，用户任选——覆盖一个人真实释放情绪的多种方式。

> **这里不要求你坚强。这里允许你暂时不用隐藏。**
>
> 但 LetOut 不是心理治疗，也不是「我们治愈你」——它只是允许你暂时不用隐藏。

### 3.1 「说出来」模式（默认，原「大声说」）

- 一个大的录音按钮，文案：「先大声说出来，再好好说。」
- 录音中波形振幅放大、配色热烈，强化「释放感」。
- 录完可立即回放，也可直接释放（不留存）。
- 不做评价、不要求说得好。不需要逻辑，不需要漂亮。

### 3.2 「喊出来」模式

- 极简：按住即录、松手即停（push-to-shout），降低「开口门槛」。
- 可选环境音/混响（Web Audio 轻量效果，纯前端），增强释放感，但默认关闭以保证轻量。
- 不产生文字、不分析内容——核心是**出声**，给压抑一个出口。

### 3.3 「唱出来」模式

- 随机弹出一句歌词或声音提示（来自 `sing-prompts.json`），作为「开口灵感」。
- 用户跟着哼/唱/喊皆可，重点不是唱得好，是**先出声**，用旋律替代语言。
- **版权与素材库**：`sing-prompts.json` 仅放「公共领域歌曲 / 用户自制短句 / 无版权灵感句」，严禁内置受版权保护的完整歌词。
  - 具体素材来源、授权方式在正式开发时单独处理（系列规范第十二节已留白）。
  - 若引用大众熟悉歌曲旋律作灵感，仅给「风格提示」文字，不内嵌受版权内容。
- 唱完同「说出来」：可回放 / 释放。

### 3.4 「哭出来」模式

- 非常克制的模式：不引导、不鼓励、不评判。
- 提供一个安静的空间，允许脆弱、难过、崩溃被自己听见。
- 可录音，也可只是静默陪伴（不录音）。重点是「允许自己难过」，而不是「表现得难过」。

### 3.5 「安静一下」模式

- 什么都不想说。没有录音按钮的压迫感。
- 真正的释放，有时候不是声音，而是**终于不用压制自己**。
- 提供一个「停一下」的入口：在这里，不说话也是被允许的。

> 五种模式共享同一录音引擎；区别只在交互入口与释放气质，不在存储逻辑。
> 「释放」比「发泄」更准：释放包含快乐、悲伤、愤怒、怀念、激动、委屈——所有真实情绪；而「发泄」偏负面，把产品窄化成了情绪垃圾桶。

## 4. IndexedDB 表结构（db.js）

数据库名：`letout`，版本：`1`。

与 SoloSpeak 同构，但**默认不长期留存** —— LetOut 的核心是释放，不是积累。

### 4.1 `releases`（释放记录）

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | string (uuid) | 主键 |
| `createdAt` | number | 创建时间 |
| `mode` | string | `speak` / `shout` / `sing` / `cry` / `quiet` |
| `durationMs` | number | 时长 |
| `audioBlob` | Blob \| null | 录音本体；**默认 null（阅后即焚）**，见 §4.2 |
| `peaks` | number[] \| null | 波形峰值（若留存则缓存） |
| `keep` | boolean | 用户是否选择「留存这条」 |

### 4.2 留存策略（关键边界）

- **默认：阅后即焚**。录完回放一次后，若不主动点「留存」，记录与音频在会话结束/明确释放后即清除（不写库，或写库后标记 `keep=false` 并定时清理）。
- 「留存」是用户主动、可逆的选择：点「留存这条」→ `keep=true` → 进入 `releases` 长期表，可后续导出（同 SoloSpeak 导出能力）。
- 不默认建立云端音频仓库（系列规范第十节精神 + RCJ 轻量优先）。
- 定时清理任务：扫描 `keep=false` 且超过保留窗口（如 24h）的记录并删除 Blob，释放空间。

> 留存窗口具体时长、是否提供「临时留存 N 天」选项，在开发阶段定，不写死。

---

## 5. 导出（与 SoloSpeak 对齐）

仅对**用户主动留存**（`keep=true`）的记录提供导出：

- TXT / Markdown / JSON（结构同 SoloSpeak §7）。
- 单条音频 `.webm` 下载（可选）。
- 默认不导出、不上传、不分析。用户拥有数据。

---

## 6. 边界与不该做的事（来自系列规范第十五节）

- 不是社交产品：无好友、私信、社区、Feed、强制注册、强制留存。
- 不是心理治疗：不诊断、不干预、不承诺「治愈」；只是允许你暂时不用隐藏。
- 释放 ≠ 社交：喊完/唱完即结束，不引导分享给「人」、不建关系。
- 不评价表达质量；重点是「先出声」。
- 不因「以后可能有很多用户」提前上复杂后端；本地优先。
